# ATU Zero Waste

Цифровая система учёта пищевых отходов университетского комплекса АО «АТУ».
Хакатон Smart Food Industries 2026, трек 1.

**Сквозной сценарий (по разделу 9 ТЗ):** QR-код на точке → записи взвешиваний со способом утилизации → отчёт за месяц одной кнопкой → проверка (принять / вернуть с комментарием) → единый реестр → дашборд → сводный отчёт за месяц/квартал/год в Excel/PDF.

**Модель:** запись = одно взвешивание (дата, наименование отходов, вес/объём, способ переработки/утилизации из справочника, ответственное лицо — как в действующих таблицах АТУ). Отчёт = все записи организации за месяц.

**Организации из ТЗ:** Столовый комплекс корп. 1, 2 (ИП «Искандер»), Учебно-гостиничный комплекс ATU INN, Кофейня АТУ (ИП «Canella»), Кафедра ТПП, Кафедра ТХиПП. Виды отходов — по образцам их таблиц.
**Наша фишка:** «Не выбросить, а отдать». Съедобные излишки (нереализованная продукция, образцы кафедр) сразу при записи публикуются на странице «Излишки» и в Telegram-канале для студентов.

## Интерфейс

Каждая роль видит только своё:
- **Ответственное лицо:** плитки с видами отходов (итог дня и месяца на каждой), нажатие открывает «весы»: вес, способ утилизации, излишек, фото. Каждое взвешивание — отдельная запись, сохраняется сразу. Внизу «Отправить отчёт за месяц».
- **Проверяющий:** «Входящие» с причинами ручной проверки, таблица сдачи отчётов по месяцам (кто не сдал). Принять или вернуть с комментарием можно прямо из списка.
- **Руководство:** «Обзор». Фраза-итог, сравнение «месяц к месяцу» за одинаковое число дней, 4 графика сразу (динамика по месяцам, структура, сравнение организаций, способы утилизации) и список «Что сделать» с экономией в тенге.

## Что упрощает работу

- **Вход по QR + PIN.** Сотрудник сканирует QR и один раз вводит 4 цифры, телефон запоминает вход. В демо: `1111` Искандер, `2222` ATU INN, `3333` Canella, `4444` Кафедра ТПП, `5555` Кафедра ТХиПП. Меняется в «Настройках».
- **Запись сразу.** Взвешивание сохраняется в момент нажатия «Записать», итоги дня и месяца пересчитываются. Дата не может быть в будущем, ошибочную запись можно удалить до отправки, на повтор (тот же вид и вес за день) система переспрашивает.
- **Автоприёмка.** Месячный отчёт принимается сам, только если выполнены все условия: по каждому виду среднее за день не больше обычного ×1,8 и не меньше 30%, нет отдельной записи в 3 раза больше обычного взвешивания, не пропущены виды, которые у точки бывают почти всегда, нет новых видов без истории, нет комментария и это не исправление после возврата. «Обычно» — среднее за рабочий день по принятым отчётам за 90 дней до месяца. Ещё 10% нормальных отчётов случайно уходят человеку (`SPOT_CHECK=0.1`). Всё, что система приняла сама, видно во «Входящих» на вкладке «Принято системой», и любой такой отчёт можно вернуть. Выключить автоприёмку: `AUTO_ACCEPT=0`.
- **Справочники** (администратор): организации (активна / нет), виды отходов (способ по умолчанию; виды с записями не удаляются, а отключаются), способы утилизации (отмечено, какие идут в переработку — отсюда «фактически переработано, %»), пользователи с email.

### Какой ключ взять

| Провайдер | Цена | Фото | Где взять ключ | Переменная |
|---|---|---|---|---|
| **Google Gemini** (рекомендуем) | Бесплатный уровень с лимитами | да | aistudio.google.com → Get API key | `GEMINI_API_KEY` |
| Groq | Бесплатный уровень, без карты | нет | console.groq.com → API Keys | `GROQ_API_KEY` |
| Claude | Платный | да | console.anthropic.com | `ANTHROPIC_API_KEY` |

```bash
set GEMINI_API_KEY=ваш_ключ      # Windows (cmd), затем python app.py
export GEMINI_API_KEY=ваш_ключ   # Mac/Linux
```
Если задано несколько ключей, порядок такой: Gemini → Groq → Claude (или явно `AI_PROVIDER=groq`). Модели меняются через `GEMINI_MODEL` (по умолчанию `gemini-flash-latest`), `GROQ_MODEL` (`llama-3.3-70b-versatile`) и `AI_MODEL` (`claude-haiku-5-5`).

У бесплатных уровней мало запросов в минуту, но для демо хватает. Google может использовать запросы бесплатного уровня для улучшения своих продуктов. Из системы уходят только суммы по точкам и фото контейнеров, без ФИО и логинов.

## Язык и тема

- **РУС / ҚАЗ.** Переключатель в меню, на странице входа и на PIN. Выбор запоминается на год. Перевод лежит в `i18n_kk.py`: ключ — русский текст, значение — казахский. Если для строки нет перевода, показывается русский. Термины статусов взяты из казахской версии кейса. Excel и PDF выгружаются на русском, а объявления об излишках сохраняются на том языке, на котором их создали.
- **Тёмная тема.** Кнопка 🌙/☀️. По умолчанию тема как в системе телефона или компьютера, выбор запоминается в браузере. Графики перекрашиваются под тему.
- **Голосовой ввод** в казахском режиме слушает казахскую речь и понимает казахские числа («үш жарым» = 3,5).

## Деплой на Render (чтобы QR работали с телефона)

1. Залить проект в репозиторий GitHub.
2. На render.com: **New → Blueprint** → выбрать репозиторий. Render прочитает `render.yaml`.
3. Telegram, по желанию. Бот здесь только **отправляет** объявления об излишках в канал, ввода данных через Telegram нет.
   - В Telegram у @BotFather: `/newbot`, задать имя, скопировать токен.
   - Создать публичный канал (например, `@atu_izlishki`) и добавить бота администратором с правом публиковать.
   - В Render → Environment задать `TELEGRAM_BOT_TOKEN` (токен) и `TELEGRAM_CHAT_ID` (`@atu_izlishki`), затем Save.
   - Без этих переменных объявления видны только на странице «Излишки».
4. После деплоя открыть `/qr` под `admin`. QR-коды строятся по реальному адресу сайта, их можно распечатать.

На бесплатном тарифе Render диск временный: после перезапуска база пересоздаётся из `seed.py`. Для демо это удобно, данные всегда свежие. Для пилота нужен PostgreSQL или постоянный диск.

## Схемы

В папке `docs/`: процесс «как есть / как будет», архитектура и ER-диаграмма (PNG для слайдов и исходники Mermaid `.mmd`).

## Модель данных (ER)

```
organizations 1─* users                 (ответственное лицо привязано к точке)
organizations *─* waste_types           через org_waste_types = шаблон формы точки
organizations 1─* reports               (отчёт = организация + месяц, UNIQUE)
reports       1─* report_items  *─1 waste_types       (запись = взвешивание: дата, вес, излишек, фото)
report_items  *─1 disposal_methods      (способ переработки / утилизации из справочника)
report_items  *─1 users                 (ответственное лицо, создавшее запись)
waste_types   *─1 disposal_methods      (способ по умолчанию)
reports       1─* status_history        (кто, когда, какой статус, комментарий)
organizations 1─* surplus_posts         (объявления «не выбросить, а отдать»)
```

Статусы: `Черновик → Отправлено → На проверке → Принято | Возвращено (с комментарием) → Отправлено …`

## Расчёты и допущения

- **Потери, ₸** = масса в отходы × (стоимость сырья за кг + вывоз за кг).
- **Вывоз:** 3 832,5 ₸/м³, тариф Алматы с 28.06.2026. Плотность отходов ~400 кг/м³ (допущение) → ≈ 9,6 ₸/кг.
- **CO₂e** = масса, ушедшая на полигон × 0,627 кг/кг (UK DEFRA 2022, пищевые отходы). Переданное на переработку, компост или корм в CO₂ полигона не входит и не оплачивается как вывоз.
- **Стоимость сырья** по видам отходов — оценка команды, правится в «Справочниках».
- **Демо-данные** — оценки, не реальные данные АТУ. Ориентир: ~60 г отходов на порцию в университетских столовых по международным исследованиям.

## Рекомендации (правила в `analytics.recommendations`)

1. Перекос по дням недели: вид отхода в какой-то день ≥ 1,4× от среднего → скорректировать закупку.
2. Аномальный день: больше среднего + 4σ → проверить холодильник и хранение (ХАССП).
3. Рост потерь точки за 4 недели ≥ 15%.
4. Доля брака в учебной лаборатории ≥ 40% → рассчитывать сырьё под группу.
5. Перерабатываемые отходы уходят на полигон → корм или компост.

Каждая рекомендация оценена в ₸ в месяц.

## Демо-сценарий для жюри (раздел 9 ТЗ)

1. На телефоне открыть QR «Искандер» (или `/f/iskander`), PIN `1111`.
2. Внести 2–3 взвешивания: плитка → вес → способ утилизации → «Записать». Итоги дня и месяца меняются сразу.
3. «＋ Другой вид отхода» → например, «Хлебные корки».
4. «Отправить отчёт за месяц» → статус «Отправлено» (новый вид без истории → ручная проверка).
5. `proverka` → «Входящие» → вернуть с комментарием.
6. `iskander` → видит комментарий, исправляет запись, отправляет снова → `proverka` принимает. История статусов видна в отчёте.
7. «Реестр»: фильтры по дате, организации, виду, способу утилизации, статусу → Excel.
8. «Обзор»: 4 графика сразу и сравнение месяц к месяцу.
9. «Отчёты» → Квартал → Excel (итоги, по видам, по способам, журнал каждой организации) и PDF.
10. «Входящие» → «Сдача отчётов»: Кафедра ТПП не исправила октябрьский отчёт — «не сдан».

Автотест этого сценария целиком: `python tests_demo.py` (нужна свежая база: `python seed.py`).
