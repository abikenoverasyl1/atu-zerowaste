# ATU Zero Waste

Цифровая система учёта пищевых отходов университетского комплекса АО «АТУ».
Хакатон Smart Food Industries 2026, трек 1.

**Сквозной сценарий:** QR-код на точке → форма со смартфона → проверка → единый реестр → дашборд → сводный отчёт в Excel/PDF.
**Наша фишка:** «Не выбросить, а отдать». Съедобные излишки лабораторий и ATU Inn публикуются в Telegram-канал для студентов.

## Интерфейс

Каждая роль видит только своё:
- **Повар или лаборант:** плитки с видами отходов, нажатие открывает «весы» с крупной цифрой и клавиатурой. Внизу одна кнопка «Отправить».
- **Проверяющий:** «Входящие». Принять или вернуть отчёт можно прямо из списка, подозрительные значения подсвечены.
- **Руководство:** «Обзор». Одна фраза-итог, один график с переключателем и список «Что сделать» с экономией в тенге.

## Что упрощает работу

- **Вход по QR + PIN.** Сотрудник сканирует QR и один раз вводит 4 цифры, телефон запоминает вход. В демо PIN = номер точки ×4: `1111` — столовая главного корпуса, `5555` — лаборатория хлебопечения, и так далее. Меняется в «Настройках».
- **Взвешивания складываются.** Каждое новое взвешивание прибавляется к итогу дня («было 2,9 → станет 4,4 кг»), черновик сохраняется сам. Есть режим «Исправить итог».
- **Автоприёмка.** Отчёт принимается сам, только если выполнены все условия: вес не больше обычного ×1,8 и не меньше 30% от него, не пропущены виды отходов, которые у точки бывают почти всегда, по каждому виду есть 5+ прошлых записей, нет комментария и это не исправление после возврата. «Обычно» — среднее у точки за 45 дней без последней недели, с учётом дня недели. Ещё 10% нормальных отчётов случайно уходят человеку (`SPOT_CHECK=0.1`). Всё, что система приняла сама, видно во «Входящих» на вкладке «Принято системой», и любой такой отчёт можно вернуть. Выключить автоприёмку: `AUTO_ACCEPT=0`.
- **«Сегодня отходов не было»** — одна кнопка, напоминаний не будет.

## ИИ

| Функция | Как работает | Что нужно |
|---|---|---|
| Голосовой ввод | «Очистки три с половиной» → плитка открывается с весом 3,5 | Chrome или Android, интернет. Ключ не нужен |
| Фото → вид отхода | ИИ подсказывает вид отхода и замечает мусор (пластик, упаковку). Вес по фото не оценивается | Gemini или Claude |
| Сводка для руководства | 4–6 пунктов с цифрами и действиями | С ключом пишет ИИ, без ключа — шаблон |
| Вопросы по данным | «Почему выросли потери в буфете?» | Любой ключ |

### Какой ключ взять

| Провайдер | Цена | Фото | Где взять ключ | Переменная |
|---|---|---|---|---|
| **Google Gemini** (рекомендуем) | Бесплатный уровень с лимитами | да | aistudio.google.com → Get API key | `GEMINI_API_KEY` |
| Groq | Бесплатный уровень, без карты | нет | console.groq.com → API Keys | `GROQ_API_KEY` |
| Claude | Платный | да | console.anthropic.com | `ANTHROPIC_API_KEY` |

```bash
set GEMINI_API_KEY=ваш_ключ      # Windows (cmd), затем python app.py
export GEMINI_API_KEY=ваш_ключ   # Mac/Linux
```
Если задано несколько ключей, порядок такой: Gemini → Groq → Claude (или явно `AI_PROVIDER=groq`). Модели меняются через `GEMINI_MODEL` (по умолчанию `gemini-flash-latest`), `GROQ_MODEL` (`llama-3.3-70b-versatile`) и `AI_MODEL` (`claude-haiku-5-5`).

У бесплатных уровней мало запросов в минуту, но для демо хватает. Google может использовать запросы бесплатного уровня для улучшения своих продуктов. Из системы уходят только суммы по точкам и фото контейнеров, без ФИО и логинов.

## Язык и тема

- **РУС / ҚАЗ.** Переключатель в меню, на странице входа и на PIN. Выбор запоминается на год. Перевод лежит в `i18n_kk.py`: ключ — русский текст, значение — казахский. Если для строки нет перевода, показывается русский. Термины статусов взяты из казахской версии кейса. Excel и PDF выгружаются на русском, а объявления об излишках сохраняются на том языке, на котором их создали.
- **Тёмная тема.** Кнопка 🌙/☀️. По умолчанию тема как в системе телефона или компьютера, выбор запоминается в браузере. Графики перекрашиваются под тему.
- **Голосовой ввод** в казахском режиме слушает казахскую речь и понимает казахские числа («үш жарым» = 3,5).

## Деплой на Render (чтобы QR работали с телефона)

1. Залить проект в репозиторий GitHub.
2. На render.com: **New → Blueprint** → выбрать репозиторий. Render прочитает `render.yaml`.
3. Telegram, по желанию. Бот здесь только **отправляет** объявления об излишках в канал, ввода данных через Telegram нет.
   - В Telegram у @BotFather: `/newbot`, задать имя, скопировать токен.
   - Создать публичный канал (например, `@atu_izlishki`) и добавить бота администратором с правом публиковать.
   - В Render → Environment задать `TELEGRAM_BOT_TOKEN` (токен) и `TELEGRAM_CHAT_ID` (`@atu_izlishki`), затем Save.
   - Без этих переменных объявления видны только на странице «Излишки».
4. После деплоя открыть `/qr` под `admin`. QR-коды строятся по реальному адресу сайта, их можно распечатать.

На бесплатном тарифе Render диск временный: после перезапуска база пересоздаётся из `seed.py`. Для демо это удобно, данные всегда свежие. Для пилота нужен PostgreSQL или постоянный диск.

## Схемы

В папке `docs/`: процесс «как есть / как будет», архитектура и ER-диаграмма (PNG для слайдов и исходники Mermaid `.mmd`).

## Модель данных (ER)

```
organizations 1─* users                 (ответственное лицо привязано к точке)
organizations *─* waste_types           через org_waste_types = шаблон формы точки
organizations 1─* reports               (одна форма = точка + день, UNIQUE)
reports       1─* report_items  *─1 waste_types   (масса, из неё съедобный излишек, фото)
reports       1─* status_history        (кто, когда, какой статус, комментарий)
organizations 1─* surplus_posts         (объявления «не выбросить, а отдать»)
```

Статусы: `Черновик → Отправлено → На проверке → Принято | Возвращено (с комментарием) → Отправлено …`

## Расчёты и допущения

- **Потери, ₸** = масса в отходы × (стоимость сырья за кг + вывоз за кг).
- **Вывоз:** 3 832,5 ₸/м³, тариф Алматы с 28.06.2026. Плотность отходов ~400 кг/м³ (допущение) → ≈ 9,6 ₸/кг.
- **CO₂e** = масса × 0,627 кг/кг (UK DEFRA 2022, пищевые отходы на полигоне).
- **Стоимость сырья** по видам отходов — оценка команды, правится в «Справочниках».
- **Демо-данные** — оценки, не реальные данные АТУ. Ориентир: ~60 г отходов на порцию в университетских столовых по международным исследованиям.

## Рекомендации (правила в `analytics.recommendations`)

1. Перекос по дням недели: вид отхода в какой-то день ≥ 1,4× от среднего → скорректировать закупку.
2. Аномальный день: больше среднего + 4σ → проверить холодильник и хранение (ХАССП).
3. Рост потерь точки за 4 недели ≥ 15%.
4. Доля брака в учебной лаборатории ≥ 40% → рассчитывать сырьё под группу.
5. Перерабатываемые отходы уходят на полигон → корм или компост.

Каждая рекомендация оценена в ₸ в месяц.
